S3 + Lambda: How They Work Together

Understanding the AWS architecture behind the Skillab chunking pipeline

The Analogy

📫

S3 = The Mailbox

AWS Simple Storage Service

Stores files (objects) in buckets. Can hold any file type, any size. Just storage -- it doesn't process anything.

🔔

Event Notification = The Doorbell

S3 Event Notification (configured in template.yaml)

When mail arrives (file uploaded), the doorbell rings (event fires). Without this, S3 and Lambda don't know about each other.

🧑‍💻

Lambda = The Person

AWS Lambda Function

Runs your code on demand. No server to manage. Wakes up when triggered, processes the file, goes back to sleep. You pay only for execution time.

Key point

S3 and Lambda are completely separate AWS services. They don't know about each other by default. The template.yaml file creates both AND wires them together using AWS SAM (Serverless Application Model). One file defines the entire architecture.

    contract_servicii.chunks.json

Files in input/ auto-expire after 7 days (LifecycleConfiguration in template.yaml). The .png file is ignored because the event filter requires suffix: .txt.

What Happens When You Upload a File

T + 0s
File lands in S3 input/
You run aws s3 cp factura.txt s3://bucket/input/ or drag-and-drop in the AWS console. S3 stores the file.
T + 0.1s
S3 checks event notification rules
S3 sees: "new object created". It checks the rules configured by template.yaml: does the key start with input/? Does it end with .txt? Both yes -- fire the event.
T + 0.2s
S3 sends event payload to Lambda
S3 constructs a JSON event with the bucket name and object key, and invokes the Lambda function asynchronously. This is a push -- Lambda doesn't poll.
T + 0.5s
Lambda wakes up
AWS spins up a container, loads your code (app.py), and calls lambda_handler(event, context). The function parses the event to get the bucket and key.
T + 1s
Lambda reads the file from S3
s3.get_object(Bucket=bucket, Key=key) -- Lambda reaches back into S3 to download the actual file content. The event only contains the file location, not the content.
T + 1.5s
Lambda chunks the text
chunk_text(body, size=500, overlap=50) -- splits text at sentence boundaries, creates overlapping chunks with index and position metadata.
T + 2s
Lambda writes result to S3 output/
s3.put_object(Key="output/factura.chunks.json") -- the chunked JSON is saved back to the same bucket, in the output/ prefix.
T + 2.1s
Lambda goes back to sleep
The function returns. The container may stay warm for a few minutes (in case another file comes), then AWS shuts it down. You pay only for the 2 seconds it ran.

What the S3 Event Looks Like

This is the JSON that S3 sends to Lambda. The function receives it as the event parameter.

{ "Records": [ { "eventSource": "aws:s3", "eventName": "ObjectCreated:Put", "s3": { "bucket": { "name": "skillab-demo-bucket" }, "object": { "key": "input/factura_001.txt", "size": 2048 } } } ] }

The Lambda code extracts the bucket and key from this event:

def handle_s3_event(event): for record in event["Records"]: bucket = record["s3"]["bucket"]["name"] # "skillab-demo-bucket" key = record["s3"]["object"]["key"] # "input/factura_001.txt" process_s3_object(bucket, key)

template.yaml: One File Creates Everything

AWS SAM uses this file to create all resources and wire them together. Here are the 4 key pieces:

1. The S3 Bucket
DataBucket: Type: AWS::S3::Bucket Properties: BucketName: !Ref BucketName LifecycleConfiguration: Rules: - ExpirationInDays: 7 # files auto-delete after 7 days
2. The Lambda Function
ChunkingFunction: Type: AWS::Serverless::Function Properties: CodeUri: src/ Handler: app.lambda_handler Runtime: python3.12 Timeout: 30 MemorySize: 256
3. The Wire (Event Notification)
Events: S3InputUpload: Type: S3 Properties: Bucket: !Ref DataBucket Events: s3:ObjectCreated:* Filter: S3Key: Rules: - Name: prefix Value: input/ - Name: suffix Value: .txt
4. The Dead Letter Queue
ChunkingDLQ: Type: AWS::SQS::Queue # Failed events land here after # 3 attempts (initial + 2 retries). # Nothing is lost. Inspect and # redrive from SQS console. Properties: MessageRetentionPeriod: 1209600 # 14 days
Infrastructure as code

You never click around the AWS console to set this up. One sam deploy command reads template.yaml and creates the bucket, Lambda, event wire, DLQ, IAM permissions, and CloudWatch alarm. To tear it all down: sam delete. Reproducible, version-controlled, reviewable in pull requests.

What This Lambda Does (and Doesn't Do)

What it does

Reads .txt files from S3, splits text into overlapping chunks (500 chars, 50 overlap), writes JSON with chunk metadata back to S3. That's it.

What it doesn't do

No LLM calls (no Gemini/OpenAI). No Pydantic extraction. No embeddings. No vector database. No HNSW. It's steps 1-2 of the pipeline only (Load + Chunk).

To add extraction (Lectia 3)

Add Gemini API call with response_schema=Invoice after chunking. Each chunk gets sent to the LLM for structured extraction. Save Pydantic output as JSON.

To add RAG (Lectia 4)

Add SentenceTransformer to embed each chunk. Save embeddings to PostgreSQL with pgvector. Build HNSW index. A separate watcher or second Lambda would handle this.

Error Handling: The DLQ Safety Net

Attempt 1
Lambda tries to process the file
If it fails (corrupt file, timeout, bug), AWS automatically retries.
Attempt 2
Automatic retry #1
AWS retries the same event. If it fails again, one more try.
Attempt 3
Automatic retry #2
Last attempt. If this also fails...
After 3 failures
Event goes to Dead Letter Queue (SQS)
The event is NOT lost. It sits in the DLQ for 14 days. You can inspect what failed, fix the bug, and redrive the message. A CloudWatch alarm notifies you when the DLQ is non-empty.

Two Ways to Invoke the Lambda

1. Event-driven (automatic)

Upload a file to input/ in S3. The event notification triggers Lambda automatically. This is the main use case -- no code needed, just upload a file.

# Just upload -- Lambda runs automatically aws s3 cp factura.txt s3://bucket/input/

2. Manual invoke (on demand)

Call the Lambda directly with a custom payload. Useful for reprocessing, testing, or processing inline text without S3.

# Process specific files {"bucket": "...", "keys": ["input/a.txt"]} # Or just send raw text {"text": "Some text to chunk"}

This repo is one piece of the puzzle

The lecturer built the simplest possible Lambda to demonstrate the S3 trigger pattern. In production, you'd chain multiple Lambdas or use AWS Step Functions to orchestrate the full pipeline: chunk, extract, embed, save. Each step could trigger the next through S3 events or SQS queues -- the same "doorbell" pattern, repeated.
